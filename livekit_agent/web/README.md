# Джарвис — веб-интерфейс

Живая, реагирующая на голос панель поверх настоящего LiveKit Agents бэкенда
(тот же `../worker.py`, что и десктопное приложение). React + Tailwind v4,
без кастомного конфига — токены палитры объявлены прямо в `src/index.css`
через `@theme`.

Никакого чат-бота: нет поля ввода, нет пузырей сообщений. Единственный ввод —
голос через микрофон браузера; текст на экране — это проекция речи (живая
транскрипция), а не форма.

## Что внутри

- **Орб** (`src/components/Orb.tsx`) — один и тот же акцентный цвет для всех
  состояний (`idle` / `listening` / `thinking` / `speaking`), различаются
  только паттерном движения и интенсивностью: дыхание в покое, деформация
  кольца по амплитуде голоса пользователя (реальный `AnalyserNode` на
  локальном микрофоне), вращающиеся частицы во время обработки LLM, волны
  наружу по амплитуде реального аудио ответа агента (тоже настоящий
  `AnalyserNode`, на треке, полученном через LiveKit — никакой синтетики).
- **Живая транскрипция** — подписка на `RoomEvent.TranscriptionReceived`.
- **Панель сценариев** — читает `scenarios.json` через `web_api.py`; клик по
  карточке отправляет текстовое сообщение агенту через LiveKit text stream
  (`localParticipant.sendText(..., {topic: "lk.chat"})`) — сценарий
  выполняется по-настоящему, с голосовой озвучкой, как если бы его попросили
  голосом. Пока сценарий выполняется, чек-лист шагов обновляется в реальном
  времени по отдельному стриму (`lk.scenario_progress`), который публикует
  `tools/scenarios.py`.
- **Журнал действий** — сворачиваемая панель, читает `logs/tool_calls.log`
  через `web_api.py`, стилизована под терминал (JetBrains Mono).

## Запуск

Нужны три процесса одновременно:

```bash
# 1. Голосовой воркер в режиме комнаты (НЕ console — фронтенду нужна
#    настоящая комната LiveKit, к которой подключится браузер)
cd ..
python worker.py dev

# 2. Локальный API (токены + чтение scenarios.json/логов)
python -m uvicorn web_api:app --host 127.0.0.1 --port 8787

# 3. Сам фронтенд
cd web
npm install
npm run dev
```

Откройте `http://localhost:5173`, разрешите доступ к микрофону.

## Известные ограничения

- Каждое подключение фронтенда создаёт свою комнату LiveKit
  (`jarvis-web-<random>`), а не одну общую — LiveKit автоматически
  диспетчеризует воркер только при *создании* комнаты, а не когда в уже
  существующую комнату заходит новый участник. Из-за этого голосовая сессия
  через `worker.py console` (десктопное приложение) и веб-интерфейс — это
  всегда две независимые беседы, не общий контекст.
- Прогресс сценария и транскрипция используют Data Streams v2
  (`send_text`/`registerTextStreamHandler`) — старый пакетный API
  `publish_data`/`dataReceived` в связке с этой версией сервера/клиента
  молча не доставлял сообщения (вызов на Python-стороне не бросал исключение,
  но событие никогда не приходило в браузер), поэтому от него отказались.
