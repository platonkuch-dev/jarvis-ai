## 2. Сквозные механизмы

### 2.1 Персистентная память — **реально используется**, не мёртвый код
`main.py:796-797` внутри `_build_config()` вызывает `load_memory()` + `format_memory_for_prompt()`
и вставляет результат прямо в `system_instruction` (`main.py:809-817`). Запись через
`save_memory` реально попадает в `%APPDATA%\Jarvis\long_term.json` (`memory_manager.py:189-196`).

**Оговорка:** `_build_config()` строится один раз на реконнект — Gemini Live не обновляет
`system_instruction` на лету. Факт, сохранённый в текущей сессии, начнёт влиять на поведение
только со следующего реконнекта, не в том же разговоре, где его сказали.

### 2.2 Pattern learning — подключено, не мёртвый код
`log_tool_call()` (`main.py:836`) вызывается на каждый tool-call. Раз в `ANALYZE_EVERY` вызовов
фоново дёргает Claude, извлекает поведенческие паттерны из `usage_log.jsonl` и пишет обратно в
`memory["preferences"]` (`pattern_learning.py:110`). Цепочка память → промпт → pattern_learning →
память замкнута и работает при наличии Claude-ключа (он в конфиге есть). Без ключа —
тихий no-op (ожидаемо, по докстрингу best-effort).

### 2.3 Proactive-режим — **не то, что заявлено, и есть конкретный баг навязчивости**
Триггер — жёсткий таймер (`actions/proactive.py:29-38`, `time.monotonic()` vs
`min_silence_secs=900`), без учёта контекста (чем занят пользователь, время суток, активное
окно) — вопреки заявлению readme "no hardcoded rules, Gemini decides". Gemini реально решает
только содержание сообщения, не факт, говорить ли вообще — механизма промолчать нет:
раз turn отправлен с `turn_complete=True`, модель почти гарантированно что-то произнесёт вслух.

**Конкретный баг, не гипотетический:** `_last_triggered` обновляется при каждом срабатывании
(`main.py:1466`), но `last_user_speech` не обновляется собственной речью ассистента. Если
пользователь ушёл/молчит долго, первое срабатывание — через 15 минут, но **каждое следующее —
уже через 10 минут, бесконечно**, пока пользователь не ответит.

### 2.4 Vision cooldown / echo-guard — работает для экрана, растянут для камеры
4-секундный cooldown для `angle=screen` реален и близок к заявленному (`main.py:906-913`,
release происходит быстро, `main.py:1355-1357`). Для `angle=camera` эффективная блокировка
растягивается на всё время голосового ответа + 2с (`_cam_close` со `sleep(2.0)`,
`main.py:1351-1364`) — то есть 5-15+ секунд, в течение которых `screen_process` для **чего
угодно** (не только повторного запроса камеры) отклоняется. Сброс при реконнекте подтверждён.
Легитимный быстрый повторный запрос в эти секунды получит явный отказ, который сам просит
модель не пытаться снова — то есть пользователю придётся переспросить вручную позже.

## 5. Что не аудировалось в эту сессию (и почему)

- Полный голосовой цикл (STT→Gemini Live→TTS) end-to-end — нет живого микрофона в этой среде;
  проверялись сами tool-обработчики, не голосовой ввод/распознавание.
- `native-core/`/`agent-ts/` — экспериментальная параллельная ветка, не подключена к голосовому
  циклу; её судьба (продолжать/заморозить/удалить) — предмет Стадии 2, не аудита полезности.
- `computer_control`'s синтез клавиатуры/мыши и `window_manager`/`ui_automation`'s click/type —
  не выполнялись вживую намеренно (риск задеть реальный десктоп пользователя во время аудита),
  оценены только по коду.
- `send_message` на реальном Telegram — не выполнялось намеренно (необратимо, видно третьей
  стороне), хотя конфигурация на этой машине рабочая.

## Итог

Проект **не является демкой** — большая часть базовых и системных инструментов (open_app,
файлы, скриншоты, память, code_helper, computer_settings, windows_control, game_updater,
reminder) реально работает end-to-end, не только "импортируется без ошибок". Но в текущем виде
ему нельзя доверять задачи без присмотра по трём независимым причинам: (1) два конкретных
вектора произвольного/непроверенного выполнения кода (`file_processor.run`,
`desktop_control.task`), (2) россыпь необратимых действий без единого шага подтверждения
(файлы, сообщения, WiFi, выключение по завершении апдейта), (3) минимум две фичи из readme,
которые пользователь ожидает как рабочие, на деле являются заглушками (`weather_report`,
`youtube_video` trending) или не существуют вовсе (Morning Briefing).
