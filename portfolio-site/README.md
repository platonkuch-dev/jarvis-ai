# Portfolio site — JARVIS AI case study

Static site (HTML / CSS / JS + Three.js) on Cloudflare Pages, with a small backend in Pages Functions and a D1 (SQLite) database
for order requests, download counts and visit stats. Opened as a plain file (`index.html`), the site still works; only the form and stats need the server.

## Before publishing — edit these
1. `src/main.js` → `SITE` block at the top: `fiverrUrl`, `email` (`name` is already Platon_ind). Then run `build.bat` (needs Node.js).
2. `index.html` → the hero copy and FAQ answers, so they match what you actually sell on Fiverr.

## Structure
- `index.html`   markup and content
- `style.css`    design tokens, layout, animations
- `src/main.js`  source: 3D scene, scroll animations, terminal demo, lead form, visit beacon
- `app.js`       built bundle (three.js included) — generated by `build.bat`
- `admin.html`   private dashboard: leads, downloads, visits (password = `ADMIN_KEY`)
- `deploy/`      what gets published — `build.bat` copies the files above into it
- `functions/`   backend (Cloudflare Pages Functions)
  - `api/lead.js`   `POST /api/lead` — saves a request from the form, pings you in Telegram
  - `api/hit.js`    `POST /api/hit` — one page view (no cookies; IPs are only stored as a daily salted hash)
  - `dl/[file].js`  `GET /dl/jarvis` — counts the download, redirects to the `.exe` of the latest GitHub release
  - `api/admin.js`  `GET/POST /api/admin` — data for `admin.html`, needs `Authorization: Bearer <ADMIN_KEY>`
- `migrations/`  database schema (`leads`, `downloads`, `page_views`)
- `wrangler.toml` Cloudflare config
- `vendor/`      three.js r170 (MIT)

## Languages (EN / RU)
English text lives in `index.html`; Russian text is in `src/i18n.js` under the same `data-i18n` keys
(placeholders use `data-i18n-ph`, form messages are in `RU_META.form`). Edit both places, then run `build.bat`.

## Deploy to Cloudflare (once)
```
npx wrangler login                                   # opens the browser, sign in to Cloudflare
npx wrangler d1 create jarvis-site-db                # copy the printed database_id into wrangler.toml
npx wrangler d1 migrations apply jarvis-site-db --remote
npx wrangler pages project create jarvis-ai-site --production-branch main
npx wrangler pages secret put ADMIN_KEY              # admin.html password
npx wrangler pages secret put IP_SALT                # any long random string
npx wrangler pages deploy                            # publishes deploy/ + functions/
```
Optional Telegram notifications about new leads: create a bot with @BotFather, send it any message, take your chat id from
`https://api.telegram.org/bot<TOKEN>/getUpdates`, then `wrangler pages secret put TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID`.

After changes: `build.bat`, then `npx wrangler pages deploy`.

## Public address: Netlify front
Some providers block `*.pages.dev`, so the public address is **https://jarvis-ai-assistant-372.netlify.app**.
Netlify serves the same `deploy/` files and its edge function (`netlify/edge-functions/proxy.js`, routes in `netlify.toml`)
forwards `/api/*` and `/dl/*` to the Cloudflare backend server-side, adding the visitor's IP and country plus the shared
`PROXY_KEY` (Netlify env var + Cloudflare secret; local copy in `.proxy_key`, not committed). So the form, stats, downloads
and `/admin.html` all work there, also for visitors who can't reach pages.dev.
Deploy after `build.bat`: `npx netlify-cli deploy --prod --dir deploy --site 36b0c895-a166-431e-a7f0-db4b05968380`
(and `npx wrangler pages deploy` if `functions/` changed).

## Tracking links
Add `?utm_source=<name>` to links you post, so the dashboard shows where people came from:
`https://jarvis-ai-assistant-372.netlify.app/?utm_source=tiktok`, `?utm_source=reddit`, `?utm_source=fiverr`. Download links can carry it too: `/dl/jarvis?utm_source=reddit`.
Without it, the source is guessed from the referrer (TikTok and Reddit apps often send none, so they show up as `direct`).
